Manual: re-vincular cuentas contables

Guía para consultores · Odoo 19 · Localización Venezuela (ve) · Odoo.sh

1. ¿Para qué sirve este script?

A veces una empresa en Odoo pierde el "enlace" interno entre sus cuentas contables y el plan de cuentas oficial de Venezuela. Las cuentas siguen visibles, pero Odoo ya no las reconoce como las del plan; por eso algunas funciones (impuestos, diarios, reportes) fallan o piden cargar el plan otra vez.

El script vuelve a conectar esas cuentas con el plan. Si alguna cuenta del plan realmente no existe, la crea de nuevo.

Una analogía sencillaPiense en un archivador con carpetas (las cuentas) y un índice (los enlaces). Si el índice se borra, las carpetas siguen ahí, pero nadie las encuentra. El script reconstruye el índice y solo crea una carpeta nueva si de verdad falta.

2. ¿Es seguro? ¿Duplica cuentas?

En el caso normal no duplica. Antes de crear una cuenta, Odoo la busca de tres maneras:

  1. Por su identificador interno (el "enlace").
  2. Si no lo encuentra, por su código (por ejemplo 1.1.01.001). Si hay una cuenta con ese código, la re-vincula en vez de crear otra.
  3. Como último respaldo, Odoo prohíbe tener dos cuentas con el mismo código en una empresa: si algo intentara duplicarla, el proceso falla con un error y no se guarda nada.
Condición para que esto apliqueLa empresa debe tener ya instalado el plan ve. Se comprueba en el paso 4 de la sección 5.
Ojo: "force_create=True" no se limita a las cuentasEsa opción también puede recrear impuestos, grupos de impuestos, diarios y posiciones fiscales que falten. Por eso se prueba primero en staging y se comparan los números antes y después (sección 5).

3. ¿Por qué a veces sí se duplican cuentas?

El análisis del caso Donarca detectó dos causas probables. Ambas rompen el enlace y el script entonces no reconoce la cuenta:

CausaQué pasa
Instalar y desinstalar el módulo l10n_ve_binauralAl instalarlo crea cuentas propias. Al desinstalarlo no las borra; quedan en la base de datos.
Borrar cuentas a manoAl eliminar cuentas manualmente se pierde el enlace. Al correr el script, Odoo no las encuentra y vuelve a crearlas.

Lo más probable en el caso reportado: alguien eliminó cuentas contables en el ambiente de release y se perdió el enlace.

4. Antes de empezar (checklist)

  • ☐ Tener acceso a Odoo.sh con permisos sobre la rama de staging.
  • ☐ Saber el nombre de la empresa a corregir (se corrige una por una).
  • ☐ Confirmar que nadie está borrando cuentas ni instalando módulos mientras se hace esto.
  • ☐ Tener un respaldo reciente de producción (Odoo.sh → Backups).
Regla de oroNunca ejecutar primero en producción. Siempre primero en staging, verificar, y solo entonces repetir en producción.

5. Paso a paso

  1. Preparar staging con datos reales. En Odoo.sh, abra la rama de staging y reconstruya la base desde un respaldo de producción (Backups → Restore / Import, o cree el staging desde producción). Así prueba con los mismos datos que tiene el cliente.
  2. Abrir la Shell. En Odoo.sh entre a la rama de staging → build activo → pestaña Shell. Aparece una terminal; espere el símbolo >>>.
  3. Encontrar el ID de la empresa. Copie y pegue: 
    for c in env['res.company'].search([]):
    print(c.id, c.name, c.chart_template)
    Anote el ID de la empresa a corregir.
  4. Confirmar que usa el plan ve. En la lista anterior, la tercera columna debe decir ve. Si dice otra cosa o está vacía, detenga el proceso y consulte al equipo técnico: el caso ya no es el "simple" descrito en este manual.
  5. Tomar una "foto" antes. Cambie 2 por el ID de su empresa: 
    company = env['res.company'].browse(2)   # ID de la empresa
Model = {m: env[m].with_company(company) for m in
         ('account.account','account.journal','account.tax','account.fiscal.position')}
antes = {m: r.search_count([('company_ids', 'in', company.id)] if m == 'account.account'
         else [('company_id', '=', company.id)]) for m, r in Model.items()}
print(antes)
    Guarde el resultado (cópielo a un bloc de notas).
  6. Ejecutar el script del gist. 
    env['account.chart.template'].with_company(company)._load(
    've', company, install_demo=False, force_create=True
)
    Todavía no guarde nada: hasta aquí los cambios son temporales.
  7. Tomar la foto después y comparar. 
    despues = {m: r.search_count([('company_ids', 'in', company.id)] if m == 'account.account'
           else [('company_id', '=', company.id)]) for m, r in Model.items()}
print(antes); print(despues)

# Códigos de cuenta repetidos (debe salir vacío)
from collections import Counter
codes = Counter(env['account.account'].with_company(company).search(
    [('company_ids', 'in', company.id)]).mapped('code'))
print([c for c, n in codes.items() if n > 1])
  8. Decidir.
    ResultadoQué hacer
    Números iguales o con pocas cuentas nuevas (las que faltaban) y lista de repetidos vacíaTodo bien. Ejecute env.cr.commit() para guardar.
    Aparecen muchas cuentas nuevas, impuestos o diarios que no esperaba, o códigos repetidosEjecute env.cr.rollback() (descarta todo) y no continúe. Avise al equipo técnico con las dos "fotos".
  9. Validar a mano en staging. Revise en Contabilidad: Plan de cuentas (sin duplicados), Diarios, Impuestos, y cree una factura de prueba. Pida al cliente que confirme.
  10. Repetir en producción. Solo si el staging salió bien: haga un respaldo de producción, repita los pasos 2 a 9 con el ID de la empresa en producción, en un horario de poco uso.
  11. Si el cliente tiene varias empresas, repita para cada una, una por una, cambiando el ID.
Sobre el script originalEl gist original ejecuta el _load y hace env.cr.commit() inmediatamente. Este manual separa el guardado para que usted pueda revisar antes de confirmar. Los pasos 5, 7 y 8 son lecturas de seguridad; no modifican datos.

6. Cómo evitar inconvenientes

No hagaHaga
Ejecutar directo en producciónProbar siempre en staging con una copia reciente
Borrar cuentas contables a mano para "limpiar"Archivar la cuenta, o consultar al equipo técnico
Instalar/desinstalar l10n_ve_binaural repetidamenteInstalarlo una sola vez, planificado
Correr el script en varias empresas a la vezUna empresa por ejecución
Guardar (commit) sin comparar númerosComparar antes/después y recién guardar
Ignorar un error rojoHacer env.cr.rollback() y reportarlo con el texto completo del error

7. Si algo sale mal

  • Aparece un error (ValidationError, código duplicado, etc.): es la protección de Odoo funcionando. No se guardó nada. Ejecute env.cr.rollback() y envíe el mensaje completo al equipo técnico.
  • Ya guardó y los números no son los esperados: no intente borrar cuentas a mano. Restaure el respaldo de producción y avise al equipo técnico.
  • La Shell se desconecta: los cambios sin commit se pierden; vuelva a empezar en el paso 2.

8. Resumen para recordar

  1. Staging primero, con datos reales.
  2. Confirmar que la empresa usa ve.
  3. Foto antes → ejecutar → foto después.
  4. Sin duplicados y números razonables → guardar; si no → rollback.
  5. Recién entonces, producción con respaldo.
